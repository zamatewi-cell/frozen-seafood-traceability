# Phase 1 测试与验收计划

## 1. 目标

验证产品原型、权限、数据模型和 API 契约能够共同支撑 PRD 的 P0 闭环。Phase 2 编码后按本计划实现自动化；本阶段先固定用例编号、数据和预期结果。

## 2. 测试层级

| 层级 | 工具候选 | 必测内容 | 门槛 |
|---|---|---|---|
| Java 单元 | JUnit 5 + AssertJ | 状态机、数量平衡、单位换算、环检测、规则判定 | 核心 Domain 分支覆盖 |
| 服务集成 | Spring Boot Test + Testcontainers MySQL 8.4 | 事务、约束、组织隔离、递归查询、迁移 | 全部通过 |
| API 契约 | MockMvc/REST Assured + OpenAPI 校验 | 状态码、错误码、白名单、幂等 | P0 端点通过 |
| 前端组件 | Vitest + Vue Test Utils | 表单校验、权限态、双时间、单位 | P0 组件通过 |
| 端到端 | Playwright | 三条演示链、异常闭环、消费者查询 | 核心旅程通过 |
| 性能 | k6 或 Gatling | 1,000 批次、10,000 事件、20 并发 | 满足 PRD P95 |
| 安全 | 自动化 + 人工检查 | 越权、上传、公开字段、日志和会话 | 无 S0/S1 |

## 3. P0 验收用例

| 用例 | 场景 | 前置数据 | 预期结果 |
|---|---|---|---|
| TC-FR-AUTH-001-01 | 企业操作员跨组织读取批次 | 组织 A/B 各有私有批次 | 403 `ORG_SCOPE_DENIED`，产生拒绝审计 |
| TC-FR-BATCH-001-01 | 创建批次草稿并提交 | 有效产品与组织 | 批号组织内唯一，提交后不可物理删除 |
| TC-FR-BATCH-002-01 | 两批合并并拆成两批 | 600 kg + 420 kg | 480 + 520 + 20 kg 平衡，谱系双向可达 |
| TC-FR-BATCH-002-02 | 数量不平衡 | 投入 500 kg、产出 1,000 kg | 422 `BATCH_MASS_BALANCE_VIOLATION`，不产生边 |
| TC-FR-BATCH-002-03 | 创建谱系环 | A→B→C 后提交 C→A | 422 `BATCH_RELATION_CYCLE`，事务回滚 |
| TC-FR-EVENT-001-01 | 补录业务事件 | 业务时间早于录入时间 | 同时保留两个时间，UI 不标成实时 |
| TC-FR-EVENT-001-02 | 更正已提交事件 | 一条已提交事件 | 原记录保留，新记录指向原记录并审计差异 |
| TC-FR-TRANSFER-001-01 | 接收方接受交接 | `PENDING` 交接 | 变为 `ACCEPTED`，记录双方与双时间 |
| TC-FR-TRANSFER-001-02 | 接收方拒收 | 填写差异和原因 | 变为 `REJECTED`，无持有权转移 |
| TC-FR-TRANSFER-001-03 | 重复接受 | 同一幂等键重放 | 返回原结果，不重复写事件 |
| TC-FR-COLD-001-01 | 不同环节使用不同规则 | 捕捞 -0.6℃、速冻 -32.4℃、运输 -20.3℃ | 均按各自规则判定正常 |
| TC-FR-COLD-001-02 | 运输温度超限 | 运输 -15.6℃，上限 -18℃ | 创建告警并绑定规则版本 |
| TC-FR-QA-001-01 | 检测不合格 | `FAIL` 报告 | 创建质量告警；页面不宣称机构真实性 |
| TC-FR-TRACE-001-01 | 任意批次正反向追溯 | 合批+拆分图 | 节点和边与预置答案一致，无重复/丢失 |
| TC-FR-TRACE-001-02 | 深度/节点上限 | 人工构造大图 | 返回 `truncated=true`，服务稳定 |
| TC-FR-TRACE-002-01 | 消费者查询有效码 | 激活公开 ID | 只返回白名单与模拟数据声明 |
| TC-FR-TRACE-002-02 | 查询不存在/停用码 | 无效和停用 ID | 统一安全提示，不泄露内部 ID |
| TC-FR-TRACE-002-03 | 查询召回码 | 召回中批次 | 显著显示模拟召回提示 |
| TC-FR-RISK-001-01 | 告警到召回闭环 | 高风险运输告警 | 确认→冻结→范围→召回→处置→关闭全留痕 |
| TC-FR-RISK-001-02 | 冻结批次继续流转 | `FROZEN` 批次 | 409 `BATCH_FLOW_BLOCKED` |
| TC-FR-AUDIT-001-01 | 检查关键写审计 | 完成建批、交接、冻结 | 用户、组织、对象、时间、请求 ID、结果齐全 |

## 4. 公开字段泄漏测试

对消费者响应执行 JSON Schema `additionalProperties: false` 校验，并维护禁止字段词典：`id`（内部主键）、`userId`、`username`、`phone`、`deviceNo`、`internalNote`、`storageKey`、`passwordHash`、`tokenHash`。任何新增公开字段都必须修改 PRD、OpenAPI 和测试。

## 5. 非功能验收

- 批次详情/谱系查询：1,000 批次、10,000 事件、20 并发时 P95 ≤ 2 s。
- 消费者首屏：同一环境 P95 ≤ 3 s。
- 表单保存/二维码生成：P95 ≤ 2 s。
- Chrome 与 Edge 当前稳定版；消费者宽度 360、390、480 px。
- 键盘可完成主流程，焦点可见；状态不只依赖颜色；图表提供文本摘要。
- 全量迁移能在空 MySQL 8.4 执行，重复启动不重复 seed。

## 6. 缺陷门槛

- S0/S1 必须为 0 才可进入发布候选。
- S2 必须关闭或有经评审的范围降级与绕行方案。
- S3 可记录为已知问题，但不得影响关键信息理解和演示。

## 7. Phase 1 设计一致性检查

- 页面动作均存在 RBAC 权限定义。
- 页面字段均能在数据字典或公开投影找到。
- OpenAPI 请求不允许客户端指定可信的 `recordedAt`、当前组织或判定结果。
- 所有数量示例满足守恒，所有温度示例按环节规则判定。
