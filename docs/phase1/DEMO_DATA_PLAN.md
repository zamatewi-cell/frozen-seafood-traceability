# 演示数据计划

## 1. 原则

- 全部组织、人员、证照、报告、车辆和设备编号均为虚构数据，并使用 `DEMO`/`SIMULATED` 标识。
- 每次 seed 结果稳定、可重复，能够与测试用例和答辩脚本一一对应。
- 不在仓库保存生产密码；演示账号通过初始化命令生成或首次启动重置。
- 日期基准为 2026-09-03，后续可整体平移，但业务时间与系统时间差必须保留。

## 2. 三条演示链

### DEMO-CHAIN-A：正常合批与拆分

目标：覆盖多源合批、加工损耗、下游拆分、证据链和消费者正常查询。

```text
辽宁扇贝 600 kg ─┐
                  ├─ 加工操作 ─ 冷冻扇贝柱 1,000 kg ─┬─ 480 kg 锦程冷链
山东扇贝 420 kg ─┘               + 损耗 20 kg        └─ 520 kg 海联冷链
```

- 公开追溯 ID：使用固定 seed 生成的不可猜测演示值，文档不写内部 ID。
- 温度：捕捞 -0.6℃、速冻 -32.4℃、冷库 -19.7℃、运输 -20.3℃、接收 -19.1℃。
- 规则：分别为 -2～4℃、≤-30℃、≤-18℃、≤-18℃、≤-18℃；均判定正常。
- 证据：捕捞记录、来源凭证、加工记录、封签照片、模拟检验报告、运单、签收单，其中一张运单可设为“待补”展示状态。

### DEMO-CHAIN-B：运输超温与模拟召回

目标：覆盖超温告警、冻结、波及面、在途/库存/已售分类和四步处置。

- 产品：冷冻鱿鱼胴体；输入 2,100 kg，损耗 40 kg，产出 2,060 kg。
- 异常：运输环节 22:37–22:52 记录 -15.6℃，该任务示例上限 -18℃。
- 影响范围：库存 900 kg、在途 360 kg、已售 800 kg；总量与产出一致。
- 状态：告警 `OPEN` 起始，演示时依次推进到模拟召回 `IN_PROGRESS`。
- 数据来源：`SIMULATED`，不得显示真实设备实采。

### DEMO-CHAIN-C：检测不合格与交接拒收

目标：覆盖检测告警、接收方拒绝、追加更正和消费者停用码。

- 产品：冷冻鲭鱼段；来源类型为进口（资料人工登记）。
- 检测：模拟报告结论 `FAIL`，`institution_verified=false`。
- 交接：因包装破损和数量差异拒收，必须填写原因。
- 更正：业务事件首次录错发货数量，追加更正记录，不覆盖原记录。
- 公开码：`DISABLED`，消费者看到安全的停用提示。

## 4. Seed 分层

| 文件 | 内容 | 是否默认 |
|---|---|---:|
| `R__reference_data.sql` | 单位、事件类型、状态字典 | 是 |
| `V009__seed_demo_master_data.sql` | 演示组织、产品、规则、角色 | 仅 demo profile |
| `V010__seed_demo_trace_chains.sql` | 三条演示链及异常 | 仅 demo profile |
| `expected-genealogy.json` | 每条链预期节点与边 | 测试资产 |
| `expected-public-fields.json` | 消费者白名单快照 | 测试资产 |

实际实现时优先由 Java seed 工具调用领域服务生成复杂业务数据，避免 SQL 绕过数量平衡、环检测和审计；SQL 只用于稳定基础字典。

## 5. 数据验收脚本输出

seed 完成后必须输出而不泄露密码：

- 数据集版本与生成时间。
- 三条链的公开演示码。
- 每条链的批次数、事件数、温度记录数、告警数。
- 数量平衡校验结果。
- 正反向谱系节点/边哈希。
- 消费者公开字段 Schema 校验结果。
