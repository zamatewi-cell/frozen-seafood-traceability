# 冷冻海产品溯源平台 · 完整业务逻辑设计 v2（供演示落地）

> 目标：把从"对上游下单 → 审批 → 生产/质检 → 发货 → 收货验收 → 零售 → 消费者扫码"的每一环节做成**有真实业务动作和状态约束的流程**，而不是几个直接改状态的按钮。每个角色都能在界面演示自己环节的完整职责。

---

## 一、统一业务模型：订单驱动 + 批次追溯 + 环节审批

- **订单**：下游对上游发起，是整条链的**触发器和履约凭证**。
- **批次(Batch)**：从原料到最终商品的**账本主线**，跨组织通过交接单(Transfer)流转归属。
- **审批/质检**：关键环节引入**具名操作人 + 结果判定 + 状态约束**，杜绝"任意改状态"。
- **唯一业务编号**：采购 PO、销售 SO、批次 BATCH、交接 TF、检验 QC，贯穿可追溯。

---

## 二、11 个业务环节（每个角色职责 + 动作 + 状态机）

### 环节 1 · 下游对上游下单（采购方）
- **动作人**：`market_op`(超市)、`shop_op`(商家) —— 采购方
- **动作**：向上游供货方提交采购单（商品明细/数量/单价/期望交期）
- **状态**：`PO_SUBMITTED`（仅采购方 Org 可发起，供货方不能是同一组织）
- **业务逻辑**：金额自动由明细合计；供货方≠采购方强制校验；每单唯一 PO 号。

### 环节 2 · 供货方审批（下游采购 → 上游确认）【新增审批点】
- **动作人**：供货方操作员，如 `plant_op`(加工厂收到超市/商家的采购)
- **动作**：
  - **接受审批** → `PO_CONFIRMED`（记录"按单排产"）
  - **驳回** → `PO_REJECTED`（必填驳回原因，采购方可见）
- **鉴权**：只有 `sellerOrgId==当前Org` 能审批；采购方只能提交/取消。
- **业务逻辑**：进入确认态后供货方才可针对该单安排生产。

### 环节 3 · 按单排产 + 生产交付（供货方）【新增"对上游下单后联动"】
- **动作人**：供货方操作员 `plant_op`
- **动作**：对已 `CONFIRMED` 的采购单调用「按单排产」→ 生成加工批次草稿并**关联订单号**；随后执行批处理提交→`PROCESS` 工艺→出厂质检(PASS)→建交接单发货
- **状态**：批次 DRAFT→ACTIVE；工艺 DRAFT→SUBMITTED 生成谱系边
- **业务逻辑**：批次挂接 orderNo，形成"订单→批次→溯源"闭环。

### 环节 4 · 出厂质检（供货方质管）【新增】
- **动作人**：`plant_qa`
- **动作**：对出厂批次创建质检单，填指标/结论，提交 `PASS`（合格出厂）或 `FAIL`（返工/降级）
- **鉴权**：仅 QUALITY_MANAGER 可创建与判定；OPERATOR 只读

### 环节 5 · 冷链发货交接（供货方）
- **动作人**：供货方操作员 `plant_op`
- **动作**：创建交接单 TF（指定接收 Org）→ 提交发货(shippedAt)
- **状态**：TF_DRAFT → TF_PENDING
- **业务逻辑**：跨组织唯一合法流转方式；批次归属仍在发货方待转。

### 环节 6 · 到货验收质检（接收方）【新增，收货前置审批】
- **动作人**：接收方质管 `market_qa` / `whl_op` 侧质管
- **动作**：对到货批次做 ARRIVAL 质检；**接收方交接单 accept 前必须存在 PASS 的到货质检**
- **判定**：PASS → 可收货；FAIL → 拒收

### 环节 7 · 收货/拒收（接收方）【审批】
- **动作人**：接收方操作员 `market_op`/`whl_op`
- **动作**：对 `PENDING` 交接单执行收货：
  - 质检 PASS → **ACCEPTED**（实测数量，可含差异原因）→ 批次归属原子转移到接收 Org
  - 质检 FAIL → **REJECTED**（原因）→ 批次退回发货方
- **联动**：对应采购单 `PO_CONFIRMED → PO_RECEIVED`

### 环节 8 · 下游再加工/分装（批发/加工）
- **动作人**：`whl_op`(分装)、必要时 `plant_op`
- **动作**：接收后可 `REPACK` 分装生成新批次、或 `PROCESS` 再加工；记录事件

### 环节 9 · 零售（面向消费者）
- **动作人**：`market_op`/`shop_op`
- **动作**：创建销售单 `SO_PLACED → SO_CONFIRMED → SO_DELIVERED`（上网/到店交付）
- **业务逻辑**：销售批次可激活公开溯源码交给消费者。

### 环节 10 · 消费者扫码
- **动作人**：任何人（公开接口，无需登录）
- **动作**：输入/扫码 26 位溯源码 → 看：商品卡、公开批次、时间轴(含质检节点)、温控摘要、召回/披露声明

### 环节 11 · 系统管理【新增】
- **动作人**：`sys_admin`（ROLE_SYS_ADMIN）
- **动作**：商品主数据、组织、账号、角色 的增删改查；温控规则发布

## 四、本次需要新增/完善的清单

### 后端
1. **订单审批**：采购单新增 `PO_REJECTED` 状态；新增 `POST /orders/purchase/{id}/approve`、`/reject`（仅供货方），记录审批人与时间
2. **质检模块（新）**：表 `quality_inspection`(+迁移 V12)；`POST /batches/{id}/inspections`、`POST /inspections/{id}/result`；角色=质管
3. **交接与质检联动**：accept 前校验存在 PASS 到货质检
4. **按单排产**：`POST /orders/purchase/{id}/schedule` 生成加工批次并关联 orderNo；batch 增加 order_no 关联展示
5. **管理端**：`GET/操作 /admin/orgs、/users、/roles`（仅 sys_admin）
6. **消费者时间轴**：把质检节点并入 timeline 展示

### 前端（每个角色独立工作台）
- 登录后按角色显示导航与操作页：
  - 采购/销售首页（对上游下单+审批+收货推进）
  - 批次工作台（建批次/工艺/事件/交接发货）
  - 质检工作台（待检清单/判定）
  - 溯源查询
  - 系统管理
- 每个工作台做**状态明确的流程编排**（非裸改状态按钮）
